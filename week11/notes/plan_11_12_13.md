# Week 11 — points 11, 12, 13 (working plan)

Track B of the project: **building high-quality pan-India classifiers** (acacia, mining, water) and
evaluating them *outside* the framework, plus one real feature — a spurious-water filter (#13).
Everything reports **precision + recall + F1**, never bare accuracy (sir's rule).

## #11 — acacia/non-acacia: counts, small-crown filter, semi-supervised self-training
`week11/acacia_eval.py` + `week11/notes/acacia_eval.md`.
1. **Count crowns** acacia vs non_acacia from `data/examples/{acacia,non_acacia}.geojson`.
2. **Small-crown filter**: drop crowns whose area < 100 m² (10×10 m) — lone-tree noise. Report
   before/after counts.
3. **Semi-supervised self-training**: LinearSVC on the filtered labelled crowns → classify an
   unlabelled pixel pool over the acacia site → add the highest-confidence pixels (top margin
   percentile) as pseudo-labels → retrain, iterate K rounds. Confidence = `decision_function` margin.
4. Report **P/R/F1** on a held-out (by-crown) split, baseline vs after self-training.
5. Note the drone-RGB DINO-embedding route as the external alternative (Gaurav) — not built.

Reuse: `examples.build_training_frame`, `sampling.interior_points`/`sample_alpha`.

## #12 — mining pan-India classifier + evaluation
`week11/mining_pan_india.py` + `week11/notes/mining_pan_india.md`.
- **Positives**: mining pixels (`data/examples/mining.geojson`, AE embeddings).
- **Hard negatives (the key idea)**: sample the **buffer ring** around each mining polygon
  (`buffer(d).difference(polygon)`, d ∈ {100,200,500} m) as `not_mining` — the "tentative area around
  mines" sir described. Plus generic negatives (barren/built/greenery from `selected_polygons.geojson`),
  the water-style augmentation.
- **Within-barren framing**: the negatives are barren-like ground next to mines, so the classifier
  learns mining-vs-not *within barren*, matching "let the base map find barren, then split mining".
- Train `StandardScaler+LinearSVC(balanced)`, **hold out whole polygons** (GroupShuffleSplit), report
  **P/R/F1** for the mining class; sweep buffer distance. Pan-India (polygons from across India).
- Surface the numbers on `mc_barren_v1` (append to Evidence, keep the #9 verdict).

Reuse: `sampling`, `temporal_eval._frame_from_file`, the `week7/site_tests` holdout pattern.

## #13 — spurious-water filter + EE ground-truth evaluation
Two parts.

**(a) Feature — persistence filter.** A pixel is only water if it read water over **≥ N fortnights**
in the year (sir's "only over two fortnights we hold"). Refactor the fortnight-count image out of
`infer.water_frequency_tiles` into `_water_count_image`, add `infer.persistent_water_tiles(bbox, year,
min_fortnights, n)` → binary water mask where count ≥ N, `GET /api/water-persistent`, and a UI button
(💧≥N). This is the road/transient-water filter.

**(b) Eval vs the EE GT assets** (all readable): `week11/water_gt_eval.py` + `notes/water_gt_eval.md`.
- `GTSeasonal` (16) + `GTPerennial` (13): all water bodies → **recall** (detection rate) seasonal vs
  perennial, and how recall changes with the persistence threshold.
- `GT_BINARY_LATEST` (288; `class` 1/2, `area_sqm`): bucket by area (small vs large), report water
  **P/R/F1** + the **false-positive rate on non-water** markings (the spurious signal). Determine which
  `class` is water empirically (print each class's water-call rate). Show the threshold sweep
  {1,2,3 fortnights}: rising threshold cuts spurious FPs at some cost to seasonal recall.
- Point-based: sample interior points, predict water at D≈8 dates across the year → per-point fortnight
  count → threshold. Reuses `sentinel.sample_points` + the deployed model.
